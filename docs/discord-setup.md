# Discord setup

Votable Lists signs people in with Discord. Only members of one Discord server can sign in, and holders of one role in that server are Admins. Each deployment registers its own Discord application. This takes about ten minutes, and you don't need a bot.

You will end up with these values:

| Value                   | Where it comes from                   |
| ----------------------- | ------------------------------------- |
| `DISCORD_CLIENT_ID`     | Discord Developer Portal, OAuth2 page |
| `DISCORD_CLIENT_SECRET` | Discord Developer Portal, OAuth2 page |
| `DISCORD_GUILD_ID`      | your Discord server (Developer Mode)  |
| `ADMIN_ROLE_ID`         | a role in your Discord server         |
| `SESSION_SECRET`        | generated by you                      |
| `SITE_URL`              | your site's address                   |

## 1. Decide your site address

`SITE_URL` is the public address of your site, as an origin: scheme and host, with no path and no trailing slash.

- Deployed: `https://your-site.netlify.app`, or your custom domain such as `https://lists.example.org`. It must be `https://`.
- Local development: `http://localhost:8888`.

Discord sends people back to `<SITE_URL>/api/auth/callback` after they sign in. That URL must match a registered redirect exactly, character for character.

## 2. Create the Discord application

1. Open the [Discord Developer Portal](https://discord.com/developers/applications) and choose **New Application**. The name you give it appears on the sign-in screen, so use something your members will recognise. You can also set an icon under **General Information**.
2. Open **OAuth2** in the sidebar.
3. Copy the **Client ID**. This is `DISCORD_CLIENT_ID`.
4. Under **Client Secret**, choose **Reset Secret** and copy the value. This is `DISCORD_CLIENT_SECRET`. Discord shows it only once. Treat it like a password: never commit it or put it in a `VITE_*` variable.
5. Under **Redirects**, choose **Add Redirect** and add both of these:
   - `https://<your-site>/api/auth/callback`, using your deployed `SITE_URL`
   - `http://localhost:8888/api/auth/callback`, for local development
6. Save your changes.

You don't need anything under **Bot**, **Installation** or the OAuth2 URL generator. The app never joins your server.

## 3. Find your server and admin role IDs

1. In the Discord app, open **User Settings → Advanced** and turn on **Developer Mode**.
2. Right-click your server's icon and choose **Copy Server ID**. This is `DISCORD_GUILD_ID`.
3. Open **Server Settings → Roles**. Right-click the role whose holders should be Admins and choose **Copy Role ID**. This is `ADMIN_ROLE_ID`. Admins can create and edit lists.

Both IDs are long numbers, such as `1234567890123456789`.

## 4. Generate a session secret

```sh
openssl rand -base64 48
```

This is `SESSION_SECRET`. It signs everyone's session cookie. Use a different one for local development and for production.

## 5. Put the values where the app reads them

**Local development:** copy `.env.example` to `.env`, fill in the values, and set `SITE_URL=http://localhost:8888`. `.env` is gitignored.

**Netlify:** go to **Site configuration → Environment variables** and add each variable, with `SITE_URL` set to your deployed address. Mark `DISCORD_CLIENT_SECRET`, `SESSION_SECRET` and `TMDB_READ_TOKEN` as secret. Redeploy after changing variables.

The functions check every variable when they start. If anything is missing or malformed, the function log lists every problem at once, starting with `Invalid configuration:`.

## What members see

The first time someone signs in, Discord asks them to allow two things:

- **identify:** their username and avatar
- **guilds.members.read:** their membership of your server (nickname, server avatar and roles)

The app never asks for email. It stores only each member's Discord ID, display name and avatar URL. Discord's access token is revoked right after the membership check and is never stored. Members can download or erase their data at any time.

## How access works

- **Who can sign in:** anyone who is a member of the server at the moment they sign in.
- **Who is an Admin:** anyone who holds `ADMIN_ROLE_ID` at the moment they sign in.
- Sessions last 12 hours. After that, the site sends people back through Discord automatically. For anyone who has already approved the app, this is a quick redirect with no screen to click through. People who are signed out of Discord in that browser will need to sign in to Discord again.
- Role changes in Discord, and removals from the server, take effect at the next sign-in, so within 12 hours.
- To end every session immediately, for example after removing an Admin, change `SESSION_SECRET` and redeploy. This signs everyone out, and they sign back in with their current roles.

## Changing your domain

1. Add the new `https://<new-domain>/api/auth/callback` redirect in the Developer Portal.
2. Change `SITE_URL` in Netlify and redeploy.
3. Once the new domain works, remove the old redirect.

## Troubleshooting

| Symptom                                                             | Likely cause                                                                                                                   |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Discord shows "Invalid OAuth2 redirect_uri"                         | The registered redirect doesn't exactly match `<SITE_URL>/api/auth/callback`. Check the scheme, host, port and trailing slash. |
| Sent back to `/?login=identity.not-a-member`                        | The account isn't in the server, or `DISCORD_GUILD_ID` is wrong.                                                               |
| Sent back to `/?login=identity.invalid-login-state`                 | The sign-in took longer than 10 minutes, cookies are blocked, or the site was opened at a different address than `SITE_URL`.   |
| Sent back to `/?login=cancelled`                                    | The person chose Cancel on Discord's screen.                                                                                   |
| Every request returns 500, and the log says `Invalid configuration` | A variable is missing or malformed. The log lists each one.                                                                    |
| Signed in, but not an Admin                                         | `ADMIN_ROLE_ID` is wrong, or the role was granted after signing in. Sign out and back in.                                      |
| Changes such as delete or logout return 403 `http.bad-origin`       | The site is being opened at an address other than `SITE_URL`.                                                                  |
